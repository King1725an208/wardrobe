# 电子衣柜 PRD（v0.2 已定稿方向）

> 状态：方向已确认。形态 = 手机 PWA 网页；存储 = 纯本地；AI 属性识别提前到 M1；常穿度 = 自动计算 + 手动修改；城市 = 上海。

## 1. 背景与目标

为老婆做个人电子衣柜应用：

- 拍照录入衣服，记录属性（品牌、购买时间、价格、风格、冷暖等）
- 像电商商城一样按分类/属性浏览筛选
- 结合天气（上海）、节假日、工作日给出每日搭配建议
- 每天拍一张当日穿搭照片，形成穿衣记录
- 由穿着频率反推每件衣服的"常穿度"，辅助清理衣柜

**核心价值**：① 衣服资产可视化；② 降低"今天穿什么"的决策成本；③ 数据化识别闲置衣物。

## 2. 目标用户与形态

- 单用户（老婆本人），主要在她的手机上使用。
- **形态：PWA 手机网页**。部署一个网址 → 手机浏览器打开 → "添加到主屏幕" → 桌面图标点开即全屏应用，拍照直接调摄像头。
- **存储：纯本地**（IndexedDB 存属性与记录，照片本地存储）。因主要在她一台手机上用，本地即成立；将来换机/多设备再加云同步，数据结构预留字段即可。

## 3. 核心功能

### 3.1 衣物录入（P0）

- 拍照或相册上传
- **AI 属性识别（已提前到 M1）**：拍照后 AI 预填 分类/颜色/风格/季节，人工确认后保存；识别失败可全手动填
- 属性字段：
  - 分类：上衣 / 下装 / 连衣裙 / 外套 / 鞋 / 包 / 配饰
  - 品牌（可选）、购买时间（年月，可选）、价格（可选）
  - 颜色、风格标签（通勤/休闲/运动/甜美/正式，多选，可自定义）
  - 季节厚薄：夏 / 春秋 / 冬
  - 材质、尺码、备注（可选）
- 照片自动去背景（白底商城感）——若实现成本过高则降级为居中裁剪，P1 内可做

### 3.2 衣柜浏览（P0）

商城式界面：

- 顶部分类 Tab + 筛选器（季节、风格、颜色、常穿度、价格）
- 排序：最近购买 / 最近穿过 / 价格
- 卡片：白底图 + 关键属性；详情页：全部属性 + 穿着历史 + 编辑
- 搜索（品牌、备注）

### 3.3 每日穿搭记录（P0）

- 每天拍"今日穿搭"照片，日历视图回看
- 勾选今天穿了衣柜里哪几件（常穿度数据源）
- 可选一句心情/场合备注

### 3.4 常穿度（P0）

- 字段：`lastWornAt`、`wearCount`、自动档位 + 手动覆盖位
- 自动规则（可配置阈值）：
  - 经常穿：近 90 天 ≥ 3 次
  - 不经常：近 90 天 1–2 次 或 >180 天未穿
  - 从不：从未穿过 或 >365 天未穿
- **手动修改原则（用户已确认）**：任何一件可在详情页手动设为 经常/不经常/从不，手动值覆盖自动值，标注"手动"
- "清理建议"视图：长期未穿 + 贵但不穿 的清单

### 3.5 搭配建议（P1）

- 天气：Open-Meteo（免费无 key），城市上海，每日拉取温度/降水
- 日历：工作日 / 周末 / 法定节假日
- 规则引擎：
  - 温度 → 过滤季节厚薄（冷→冬装，热→夏装）
  - 工作日偏通勤、周末偏休闲、节假日偏正式/甜美（权重可配置）
  - 优先推"不经常穿"的衣服盘活库存
- M3 可升级 AI 搭配点评

### 3.6 数据统计（P2）

- 衣柜总价值、件数、cost per wear
- 月度穿着热力图、风格/颜色分布

## 4. 技术方案

- React + TypeScript + PWA（manifest + service worker，离线可用，可加桌面图标）
- IndexedDB（属性/记录）+ 本地照片 Blob 存储；数据模型预留 `userId`/`syncedAt` 字段便于将来云同步
- AI 识别：调视觉模型 API（需一个 API key，录入时在线，其余功能离线可用）
- 天气：Open-Meteo，上海（31.23°N, 121.47°E）

## 5. 里程碑

- **M1（MVP）**：录入（含 AI 识别+人工确认）+ 商城式浏览 + 每日穿搭记录 + 常穿度（自动+手动）
- **M2**：上海天气 + 节假日/工作日规则搭配建议 + 清理建议视图 + 照片去背景
- **M3**：AI 穿搭点评 + 数据统计 + （可选）云同步
